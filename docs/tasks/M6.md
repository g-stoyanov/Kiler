| The conflict side by side (decided by the user) | The panel of a conflict shows two columns: "Your edit", the form as it is, and the version of `current`, with who saved it and when. Each has the header (the path, the name, the description, the tags) and the fields of the template, and a row where the two differ is marked. A `secret` is never shown: "New value" on the side of the edit when the editor typed one, else "Unchanged", and "Hidden" on the other side. A field above the editor's levels has the padlock on both sides. The choice is of the whole version, not by field: "Keep mine", the old "Overwrite" (the edit over the version of `current`), and "Take theirs", the old "Reload". In a narrow window the columns stack. Only the page changes; the 409 stays as it is (`docs/api.md`, "Conflict"). |
| Merged and deleted stashes (design 6.6) | `stashes\<id>.json` gets `redirect`, the id of the stash it was merged into, and `deleted`, `true`; each is left out otherwise, and the file stays with its name. A path is read through them everywhere: the record, the list, the search text with the names, the tree and its counts, the `stash` of the query, and `used` of `GET /api/stashes`. Each id follows `redirect` to a stash without one, in at most 8 steps; a loop reads as a stash that cannot be read, as a missing one does now. A stash that the path then has twice stays only at its first position, and the path is cut before a deleted stash. The records are not written again: an edit saves the path as the form shows it, read through. `GET /api/stashes` and the check of a new name know only the live stashes. A new record or an edit that names a merged stash takes the one it leads to; one that names a deleted stash is 400 with `field` `stash`. |
| Rename, merge and delete | `Need.Admin`, each with the version of the stash, and `ChangesData()`. `GET /api/admin/stashes` gives the live stashes by name with `version` and `records`, the number of the shared records of `records\` whose path, read through, has the stash. `PUT /api/admin/stashes/{id}` with `{ "name", "version" }` renames it: the name trimmed, not blank, unique among the live stashes without regard to case, the stash itself left out. `POST /api/admin/stashes/{id}/merge` with `{ "into", "version" }` merges it into another live stash. `DELETE /api/admin/stashes/{id}?version=<n>` deletes it when `records` is 0, else 409 with the count. A record in the trash does not count: restored, its path is cut before the deleted stash. An older version is 409, and so are offline and the other outcomes of a write, as for a new stash. `/stashes` is an admin screen with the link "Stashes": the list with the counts, and on each "Rename", "Merge into …", a choice of another live stash, and "Delete", only at 0. M6.22 writes the endpoints into `docs/api.md` from this row. |
| Parallel sessions of the brought forward | As in the row "Parallel sessions": **B** M6.16 and **C** M6.20, both at once; **E**, the admin screens, M6.19 once M6.18 is committed, then M6.23 once M6.22 is.
